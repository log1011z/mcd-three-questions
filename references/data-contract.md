# 汇总脚本输入

脚本接收 UTF-8 JSON；宿主先实际调用 MCP，再把对应结果整理成此格式。脚本不连接网络，也不把输入标记当成接口调用证明。

```json
{
  "mode": "live",
  "store": "实际确认的门店名称",
  "budget_cny": "25.00",
  "selections": [
    {
      "label": "当前选择",
      "items": [
        {
          "name": "原味板烧鸡腿堡",
          "spec": "1个",
          "quantity": 1,
          "is_burger": true,
          "nutrition": {
            "energy": 400,
            "unit": "kcal",
            "serving": "1个"
          }
        }
      ],
      "quote": null,
      "reason": "符合已经确认的鸡肉偏好。"
    }
  ]
}
```

上面数字仅用于说明结构，不是板烧鸡腿堡的真实营养数据。可运行演示见 `examples/demo.json`，所有数值明确标注演示。

- `mode` 必填，只能为 `demo` 或 `live`。实时结果只有在宿主已取得真实数据时使用 `live`；无连接时不生成假 live 示例。
- `store` 为已确认门店名称。`budget_cny` 为整餐应付上限，人民币金额；不限预算时为 null。
- `selections`：中途可仅放“当前选择”；最终放“主推”“备选”两份，只有一份可行时允许只有主推。
- `items` 必须是实际选择的平铺单品。一个套餐含两个汉堡时汉堡 quantity=2，不能再次列入套餐父项。`spec` 对应单份规格，quantity 为正整数。
- `is_burger` 为布尔值。只为真实汉堡标 true，不能给含汉堡的套餐标题标 true。
- `nutrition` 为该规格**单份**数据，缺失或无法匹配时为 null；`serving` 必须等于 `spec`。`energy` 为非负数字，unit 支持 kcal / kJ / 大卡 / 千卡 / 千焦。优先取官方 `energyKcal`，包括0；仅该字段缺失时使用 `energyKj`。不能按套餐总重量或未知杯型做比例外推。
- `quote` 未完成、失败或选择已变更时为 null；完成后填 `{"source":"calculate-price","total_cny":"24.00","queried_at":"2026-10-24T15:00:00+08:00"}`。实际 `data.price` 单位为分，先除以100转元再填 `total_cny`，例如1390写为13.90。金额与时间必须取自实际计价及调用时间，示例文件除外。脚本不拆分或推算单品优惠后价格。
- `reason` 为简短推荐理由，`title` 可选，为本份选择的趣味称号。脚本不生成偏好或替宿主判断主推。

输出每份选择的单份和单项合计热量、汉堡等级及官方来源、应付价、预算差额。所有热量先使用原始精度运算，最后四舍五入为整数；因此可见的已取整分项相加偶尔与合计相差 1 kcal。

资料表只收录查证过的明确名称。新增别名需有指向该产品/系列的官方依据，不用模糊匹配或把未查证产品视为经典档。

真实只读联调快照见 `examples/live-2026-10-24.json`。它是2026-10-24的历史查询结果，不代表之后的实时价格或当前供应。
